This guide covers common issues you might encounter when using the Aranet CLI, TUI, GUI, or library, along with solutions and workarounds.

## Quick Diagnostics

Run the built-in diagnostic tool to check your system:

```bash
aranet doctor
```

This will check:
- Bluetooth adapter status
- Required permissions
- Known device connectivity
- Configuration validity

## Bluetooth Issues

<div class="not-content faq-section">

<details class="faq-item">
<summary>Device not found during scan</summary>
<div class="faq-content">

**Symptoms:** `aranet scan` returns no devices or times out.

**Solutions:**

1. **Ensure the device is in range** - Aranet devices have a Bluetooth range of approximately 10 meters (33 feet).

2. **Check if the device is paired with another app** - Some devices only allow one active connection. Close the official Aranet Home app or disconnect from other Bluetooth managers.

3. **Restart Bluetooth on your system:**

<Tabs>
  <TabItem label="macOS">
```bash
# Turn Bluetooth off and on
blueutil --power 0 && sleep 2 && blueutil --power 1
```
  </TabItem>
  <TabItem label="Linux">
```bash
# Restart Bluetooth service
sudo systemctl restart bluetooth
```
  </TabItem>
  <TabItem label="Windows">
```powershell
# Restart Bluetooth service
Restart-Service bthserv
```
  </TabItem>
</Tabs>

4. **Increase scan duration:**
```bash
aranet scan --timeout 30
```

5. **Try passive reads** if Smart Home broadcasting is enabled on the device:
```bash
aranet read --passive
aranet watch --passive
```

6. **Use the full name or address** - Since aranet 0.3.0, `--device`, `ARANET_DEVICE`, aliases and the default device set with `aranet config set device` must match one device exactly: its full name, MAC address or UUID as `aranet scan` shows it (a MAC address works with or without colons, and case doesn't matter). A partial name such as `2751B` fails with a "did you mean 'Aranet2 2751B'?" error instead of connecting. With `--passive` (item 5), give the name or address exactly as `aranet scan` shows it, case included.

</div>
</details>

<details class="faq-item">
<summary>Connection drops or times out</summary>
<div class="faq-content">

**Symptoms:** Commands fail with "connection timeout" or "device disconnected" errors.

**Solutions:**

1. **Move closer to the device** - Bluetooth Low Energy signal strength varies.

2. **Check for interference** - WiFi routers, microwaves, and other 2.4GHz devices can interfere.

3. **Retry with longer timeout:**
```bash
aranet read --device <ADDRESS> --timeout 60
```

4. **Check device battery** - Low battery can affect Bluetooth transmission power. Use:
```bash
aranet info --device <ADDRESS>
```

5. **Reset the device connection:**
```bash
# Disconnect and reconnect to the device
aranet read --device <ADDRESS>
```

</div>
</details>

<details class="faq-item">
<summary>"Permission denied" or "Access denied" errors</summary>
<div class="faq-content">

**Symptoms:** Bluetooth operations fail with permission errors.

<Tabs>
  <TabItem label="macOS">

macOS requires Bluetooth permission for terminal applications.

<Steps>
1. Open **System Settings** → **Privacy & Security** → **Bluetooth**
2. Ensure your terminal app (Terminal, iTerm2, etc.) is listed and enabled
3. If not listed, run `aranet scan` once - macOS should prompt for permission
4. Restart your terminal after granting permission
</Steps>

  </TabItem>
  <TabItem label="Linux">

Linux requires either root access or proper group membership.

**Option 1: Add user to bluetooth group**
```bash
sudo usermod -aG bluetooth $USER
# Log out and back in for changes to take effect
```

**Option 2: Grant capabilities to the binary**
```bash
sudo setcap 'cap_net_raw,cap_net_admin+eip' $(which aranet)
```

**Option 3: Configure D-Bus policy**
Create `/etc/dbus-1/system.d/aranet.conf`:
```xml
<!DOCTYPE busconfig PUBLIC "-//freedesktop//DTD D-Bus Policy//EN"
  "http://www.freedesktop.org/standards/dbus/1.0/busconfig.dtd">
<busconfig>
  <policy user="YOUR_USERNAME">
    <allow send_destination="org.bluez"/>
    <allow send_interface="org.bluez.GattCharacteristic1"/>
    <allow send_interface="org.bluez.GattDescriptor1"/>
    <allow send_interface="org.freedesktop.DBus.ObjectManager"/>
    <allow send_interface="org.freedesktop.DBus.Properties"/>
  </policy>
</busconfig>
```

Don't allow your user to own `org.bluez` (if you copied an earlier version of this policy, delete its `allow own` line): owning that name is never needed, and it would let any of your processes impersonate BlueZ.

  </TabItem>
  <TabItem label="Windows">

Windows typically doesn't require special permissions for Bluetooth, but:

1. **Run as Administrator** if you encounter issues
2. **Check Windows Bluetooth settings** - ensure Bluetooth is enabled
3. **Update Bluetooth drivers** via Device Manager

  </TabItem>
</Tabs>

</div>
</details>

<details class="faq-item">
<summary>Service discovery timed out on Linux</summary>
<div class="faq-content">

**Symptoms:** on Linux, connecting to an Aranet4 fails with `Bluetooth error: Service discovery timed out`, usually the first time this computer connects to it, or after `bluetoothctl remove`. On a slow link, where the connection itself takes more than about 10 seconds to come up, such a connect can fail with `Operation 'connect to device' timed out` instead.

**Cause:** when BlueZ connects to a sensor whose services it hasn't stored yet, it first reads them from the sensor, and an Aranet4 can take up to about 20 seconds for that. aranet 0.2.1 and earlier gave BlueZ only 5 seconds, or less when the connection itself was slow to come up, because the connect as a whole has a time limit too. By default (`Cache = always` in `/etc/bluetooth/main.conf`) BlueZ stores the services it has read. With `Cache = yes` it stores them only for paired sensors, and with `Cache = no` never, so there an unpaired sensor can fail like this on every connect.

**Solutions:**

1. **Update to aranet 0.3.0 or later.** While BlueZ is still reading the services, aranet waits for it, also when the connection was slow to come up, for at least 20 seconds (or for `ConnectionConfig::discovery_timeout`, if a program using the library sets it longer). A first connection to an Aranet4 can therefore take about 20-35 seconds, plus the pairing (up to about 40 seconds) when aranet pairs a sensor that isn't paired yet (see Pairing on Linux). The GUI gives a connection 30 seconds in all, and a first connection it gives up on is cancelled, pairing included, so the next attempt starts again from the beginning and can time out the same way: connect to a sensor for the first time on Linux with `aranet read --device <MAC>` (or pair it by hand, see Pairing on Linux), then use it in the GUI. With `--verbose`, aranet logs `BlueZ is still discovering services; waiting up to 20s in all`. If BlueZ doesn't finish in time, the connect fails with `Operation 'discover services' timed out` and aranet disconnects from the sensor.

2. **Keep the Bluetooth adapter away from USB 3 devices.** USB 3 ports, cables and disks interfere with 2.4 GHz radio, which slows down every exchange with the sensor, setting up the connection included. If a USB Bluetooth dongle sits next to a USB 3 disk or port, move it away, for example on a USB 2 extension cable.

3. **With aranet 0.2.1 and earlier,** a failed attempt can leave the sensor connected to the computer until BlueZ drops the link, so the phone app can't connect to it. Release it with:
```bash
bluetoothctl disconnect <MAC>
```

</div>
</details>

<details class="faq-item">
<summary>Pairing on Linux</summary>
<div class="faq-content">

**How it works:** since aranet 0.3.0, the first time aranet connects to a sensor that isn't paired yet, it pairs the sensor and logs `Paired with <address>`. aranet can't enter a PIN, though: a sensor that wants its PIN has to be paired by hand once (solution 2), and aranet then uses that pairing. aranet doesn't register a system-wide Bluetooth agent: its agent exists only while it pairs that sensor and approves nothing else, so the desktop's Bluetooth settings keep working while aranet runs. (aranet 0.2.1 and earlier register BlueZ's default agent for as long as they run instead.) Sensors that are already paired are used as they are. `aranet` logs pairing failures by default and `Paired with` only with `--verbose`; for `aranet-service` or `aranet server`, set `RUST_LOG=aranet_core=info` to see pairing messages, including failures.

**Symptoms:** aranet logs a warning that pairing failed or timed out, then connects anyway. This usually happens after the sensor was reset or paired with a phone. If the sensor refuses to pair (it may want its PIN), aranet doesn't try again for 10 minutes; after other failures it tries again at the next connection. Until the sensor is paired, its reads can time out on a server without a desktop Bluetooth agent: stop `aranet-service` or `aranet server` and any other aranet command that uses the sensor, then pair it by hand in an interactive `bluetoothctl` session (solution 2), entering its PIN if asked (a connect during the pairing cancels it). The one-line `bluetoothctl pair <MAC>` registers no agent, so on a server it can't ask for the PIN.

A sensor that wants its PIN can also seem to pair: an Aranet2 with BlueZ 5.82, for example, completes aranet's pairing without the PIN (aranet logs `Paired with <address>`) and then rejects that pairing, so every later connection to it fails. Removing the pairing and letting aranet pair again (solution 1) only repeats this: pair such a sensor by hand, with its PIN (solution 2).

**Solutions:**

1. **Remove the old pairing and connect again** (for a sensor that wants its PIN, use solution 2 instead):
```bash
bluetoothctl remove <MAC>
aranet read --device <MAC>
```
While `aranet-service` or `aranet server` runs, skip the `aranet read`: the service pairs the sensor again at its next poll, and a connect from a second aranet process during that pairing cancels it. If the sensor refused to pair, the service waits until the 10 minutes are up, or tries at once if you restart it.

2. **Or pair by hand in `bluetoothctl`**, then connect again; a sensor that wants its PIN can only be paired this way. First stop `aranet-service` or `aranet server` and any other aranet command that uses the sensor: a connect during the pairing cancels it. Remove the old pairing if there is one, start a scan, wait until the sensor's MAC address is listed (after `remove`, BlueZ has to find the sensor again before it can pair it), stop the scan, and pair. The sensor may show a PIN on its screen: type it when `bluetoothctl` asks for it.
```bash
bluetoothctl
# then, at the [bluetooth]# prompt:
remove <MAC>
# (if this computer has no record of the sensor, remove says so: go on)
scan on
# wait until a line with the sensor's MAC address appears, then:
scan off
pair <MAC>
quit
```

## Installation Issues

<div class="not-content faq-section">

<details class="faq-item">
<summary>Homebrew installation fails</summary>
<div class="faq-content">

**Try these solutions in order:**

1. **Update Homebrew:**
```bash
brew update
brew upgrade
```

2. **Re-tap the repository:**
```bash
brew untap cameronrye/aranet
brew tap cameronrye/aranet
brew install aranet
```

3. **Install from source instead:**
```bash
brew install --build-from-source aranet
```

4. **Check for conflicts:**
```bash
brew doctor
```

</div>
</details>

<details class="faq-item">
<summary>Cargo build fails with btleplug errors</summary>
<div class="faq-content">

**Common causes and solutions:**

**On Linux - missing D-Bus development files:**
```bash
# Debian/Ubuntu
sudo apt install libdbus-1-dev pkg-config

# Fedora/RHEL
sudo dnf install dbus-devel pkgconfig

# Arch
sudo pacman -S dbus pkgconf
```

**On macOS - missing Xcode tools:**
```bash
xcode-select --install
```

**Outdated Rust toolchain:**
```bash
rustup update stable
```

</div>
</details>

<details class="faq-item">
<summary>Shell completions not working</summary>
<div class="faq-content">

**Generate and install completions for your shell:**

<Tabs>
  <TabItem label="Bash">
```bash
aranet completions bash > ~/.local/share/bash-completion/completions/aranet
# Or for system-wide:
sudo aranet completions bash > /etc/bash_completion.d/aranet
```
  </TabItem>
  <TabItem label="Zsh">
```bash
aranet completions zsh > ~/.zsh/completions/_aranet
# Add to ~/.zshrc if not present:
# fpath=(~/.zsh/completions $fpath)
# autoload -Uz compinit && compinit
```
  </TabItem>
  <TabItem label="Fish">
```bash
aranet completions fish > ~/.config/fish/completions/aranet.fish
```
  </TabItem>
  <TabItem label="PowerShell">
```powershell
aranet completions powershell >> $PROFILE
```
  </TabItem>
</Tabs>

**Restart your shell after installing completions.**

</div>
</details>

## Data & Export Issues

<div class="not-content faq-section">

<details class="faq-item">
<summary>History download is slow or incomplete</summary>
<div class="faq-content">

Aranet devices can store weeks of data. Large downloads take time due to BLE bandwidth limitations.

**Tips for faster downloads:**

1. **Use incremental sync** - only download new data:
```bash
aranet sync --device <ADDRESS>
```

2. **Filter by date range:**
```bash
aranet history --device <ADDRESS> --since 2026-01-01 --until 2026-01-15
```

3. **Limit the number of records:**
```bash
aranet history --device <ADDRESS> --count 1000
```

4. **Download to local database for future queries:**
```bash
# Sync downloads history to the local SQLite database
aranet sync --device <ADDRESS>

# Query cached data without connecting to device
aranet cache history --device <ADDRESS>
```

</div>
</details>

<details class="faq-item">
<summary>CSV export has wrong encoding or format</summary>
<div class="faq-content">

**Specify the output format explicitly:**

```bash
# Standard CSV with headers
aranet history --device <ADDRESS> --format csv > data.csv

# JSON for programmatic use
aranet history --device <ADDRESS> --format json > data.json

# Plain text (default)
aranet history --device <ADDRESS> --format text
```

**For Excel compatibility:** Open the CSV file in Excel. If characters display incorrectly, use Excel's "Get Data from Text/CSV" import feature and select UTF-8 encoding.

</div>
</details>

<details class="faq-item">
<summary>Timestamps appear wrong</summary>
<div class="faq-content">

**Aranet devices store timestamps in UTC.** The CLI converts to your local timezone by default.

**If timestamps appear incorrect:**

1. **Verify your system timezone** is set correctly
2. **Check device interval** - history timestamps are calculated from the device's current time minus intervals
3. **Use JSON output** for precise timestamp inspection:
```bash
aranet history --device <ADDRESS> --format json
```

**If device time is significantly wrong,** you may need to reconfigure the device using the official Aranet Home app.

</div>
</details>

</div>

## TUI & GUI Issues

<div class="not-content faq-section">

<details class="faq-item">
<summary>TUI display is garbled or colors are wrong</summary>
<div class="faq-content">

**Check your terminal compatibility:**

1. **Use a modern terminal** - The TUI requires 256-color or truecolor support. Recommended: iTerm2, Alacritty, Windows Terminal, Kitty.

2. **Set TERM environment variable:**
```bash
export TERM=xterm-256color
aranet tui
```

3. **Use a terminal with solid Unicode and color support** - iTerm2, Kitty, Windows Terminal, and Alacritty work well.

4. **If rendering is still broken, verify your locale and font** so box-drawing characters and symbols are available.

</div>
</details>

<details class="faq-item">
<summary>GUI won't start or crashes on launch</summary>
<div class="faq-content">

**Common solutions:**

1. **Check system requirements:**
   - macOS 11.0+ (Big Sur or later)
   - Windows 10 version 1903+
   - Linux with GTK 3.24+ and glibc 2.35+

2. **On macOS - verify app permissions:**
   - Open System Settings → Privacy & Security
   - Check Bluetooth and Accessibility permissions

3. **Try launching from terminal** to see error messages:
```bash
# macOS
/Applications/Aranet.app/Contents/MacOS/aranet-gui

# Linux
aranet-gui
```

4. **Reset GUI settings:**
```bash
rm -rf ~/.config/aranet-gui
```

</div>
</details>

<details class="faq-item">
<summary>System tray icon not appearing</summary>
<div class="faq-content">

**Linux users:** System tray support varies by desktop environment.

- **GNOME:** Install the AppIndicator extension
- **KDE:** Should work out of the box
- **i3/Sway:** Use a status bar with tray support (e.g., Waybar, i3bar with i3blocks)

**macOS users:** The menu bar icon should appear automatically. If not, check System Settings → Control Center → Menu Bar Only.

</div>
</details>

## Frequently Asked Questions

<div class="not-content faq-section">

<details class="faq-item">
<summary>Which devices are supported?</summary>
<div class="faq-content">

Currently supported devices:

| Device | Sensors | Status |
|--------|---------|--------|
| Aranet4 | CO2, Temperature, Humidity, Pressure | Full support |
| Aranet2 | Temperature, Humidity | Full support |
| AranetRn+ | Radon, Temperature, Pressure, Humidity | Full support |
| Aranet Radiation | Dose Rate, Total Dose | Full support |

**Not yet supported:** Aranet PRO base station, Aranet Cloud integration.

</div>
</details>

<details class="faq-item">
<summary>Can I use multiple devices simultaneously?</summary>
<div class="faq-content">

Yes! The CLI, TUI, and GUI all support multiple devices.

**CLI - Read from multiple devices:**
```bash
aranet read -d living-room -d bedroom -d office
```

**TUI - Monitor multiple devices:**
```bash
aranet tui
# Press `s` to scan and `C` to connect all known devices.
```

**Set up aliases for easy access:**
```bash
aranet alias set living-room AA:BB:CC:DD:EE:FF
aranet alias set bedroom 11:22:33:44:55:66
aranet alias list
```

</div>
</details>

<details class="faq-item">
<summary>How do I integrate with Home Assistant?</summary>
<div class="faq-content">

Use `aranet-service` with MQTT enabled so Home Assistant can discover supported sensors automatically:

```bash
# Start the service
aranet-service --bind 127.0.0.1:8080
```

```toml
[mqtt]
enabled = true
broker = "mqtt://localhost:1883"
topic_prefix = "aranet"
homeassistant = true
ha_discovery_prefix = "homeassistant"
```

See the [Home Assistant integration guide](/aranet/docs/service/home-assistant/) for the full setup.

</div>
</details>

<details class="faq-item">
<summary>What are the CO2 color thresholds?</summary>
<div class="faq-content">

The Aranet4 uses the following thresholds (configurable on the device):

| Level | CO2 Range | Color | Meaning |
|-------|-----------|-------|---------|
| Good | < 1000 ppm | Green | Air quality is good |
| Warning | 1000-1400 ppm | Amber | Consider ventilating |
| Poor | > 1400 ppm | Red | Ventilation needed |

These thresholds are reported from the device, but the CLI currently exposes only interval, range, and Smart Home settings. If you need to change CO₂ warning/alarm thresholds, use the official Aranet Home app.

</div>
</details>

## Still Having Issues?

If you've tried the solutions above and still have problems:

1. **Check existing issues** on [GitHub Issues](https://github.com/cameronrye/aranet/issues)
2. **Open a new issue** with:
   - Your OS and version
   - Output of `aranet doctor`
   - Steps to reproduce the problem
   - Full error message
3. **Join the discussion** on GitHub Discussions for general questions

<Aside type="tip">
Use `--verbose` and, when needed, `RUST_LOG=debug` for richer bug reports:
```bash
RUST_LOG=debug aranet --verbose scan
```
</Aside>
