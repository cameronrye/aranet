## Global Options

These options apply to most commands:

| Option | Description |
|--------|-------------|
| `-v, --verbose` | Enable verbose logging |
| `-q, --quiet` | Suppress non-essential output |
| `--json` | Shorthand for JSON output where supported |
| `--compact` | Emit compact JSON instead of pretty-printed JSON |
| `--no-color` | Disable colored output |
| `--style <MODE>` | Visual style: `rich`, `minimal`, `plain` |
| `-o, --output <FILE>` | Write output to a file instead of stdout |

Common unit flags:

| Option | Description |
|--------|-------------|
| `--fahrenheit` / `--celsius` | Override temperature units |
| `--inhg` / `--hpa` | Override pressure units |
| `--bq` / `--pci` | Override radon units |

## scan

Discover nearby Aranet devices via Bluetooth.

```bash
aranet scan [OPTIONS]
```

| Option | Description |
|--------|-------------|
| `-t, --timeout <SECONDS>` | Scan duration in seconds |
| `-f, --format <FORMAT>` | Output format: `text`, `json`, `csv` |
| `--no-header` | Omit the CSV header row |
| `-a, --alias` | Interactively save aliases for discovered devices |

```bash
aranet scan --timeout 15
aranet scan --alias
```

## read

Read current sensor measurements from one or more devices.

```bash
aranet read [OPTIONS]
```

| Option | Description |
|--------|-------------|
| `-d, --device <ADDRESS>` | Device address or alias; can be repeated or comma-separated |
| `-T, --timeout <SECONDS>` | Connection timeout per device |
| `-f, --format <FORMAT>` | Output format: `text`, `json`, `csv` |
| `--passive` | Read from BLE advertisements without connecting |
| `--no-header` | Omit the CSV header row |

```bash
aranet read --device AA:BB:CC:DD:EE:FF
aranet read -d living-room -d bedroom
aranet read --device living-room --passive --json
```

<Aside>
  If you omit `--device`, the CLI uses the configured or last-used device when available. Otherwise it falls back to the interactive picker.
</Aside>

## history

Download historical measurements from a device, or read them from the local cache.

```bash
aranet history [OPTIONS]
```

| Option | Description |
|--------|-------------|
| `-d, --device <ADDRESS>` | Device address or alias |
| `-T, --timeout <SECONDS>` | Connection timeout |
| `-c, --count <N>` | Number of records to retrieve (`0` means all) |
| `-f, --format <FORMAT>` | Output format: `text`, `json`, `csv` |
| `--since <DATE>` | Filter records after this RFC3339 or `YYYY-MM-DD` timestamp |
| `--until <DATE>` | Filter records before this RFC3339 or `YYYY-MM-DD` timestamp |
| `--cache` | Read from the local cache instead of connecting to the device |
| `--no-header` | Omit the CSV header row |

```bash
aranet history --device living-room --output history.csv --format csv
aranet history --device living-room --since 2026-03-01 --until 2026-03-07
aranet history --device living-room --cache --count 100 --format json
```

## set

Modify supported device settings.

```bash
aranet set [OPTIONS] <SUBCOMMAND>
```

| Subcommand | Description |
|------------|-------------|
| `interval <MINUTES>` | Set the measurement interval in minutes; valid values are `1`, `2`, `5`, `10` |
| `range <MODE>` | Set Bluetooth range mode; valid values are `standard`, `extended` |
| `smart-home <BOOL>` | Enable or disable Smart Home BLE advertisements |

| Option | Description |
|--------|-------------|
| `-d, --device <ADDRESS>` | Device address or alias |
| `-T, --timeout <SECONDS>` | Connection timeout |
| `-f, --force` | Skip the confirmation prompt |

```bash
aranet set --device living-room interval 5
aranet set --device living-room range extended
aranet set --device living-room smart-home on
```

## watch

Continuously monitor a device, or all devices passively.

```bash
aranet watch [OPTIONS]
```

| Option | Description |
|--------|-------------|
| `-d, --device <ADDRESS>` | Device address or alias |
| `-T, --timeout <SECONDS>` | Connection timeout |
| `-i, --interval <SECONDS>` | Poll interval |
| `-n, --count <N>` | Stop after `N` samples (`0` means unlimited) |
| `-f, --format <FORMAT>` | Output format: `text`, `json`, `csv` |
| `--passive` | Watch BLE advertisements instead of opening a connection |
| `--no-header` | Omit the CSV header row |

```bash
aranet watch --device living-room --interval 30
aranet watch --passive
aranet watch --device basement --passive --count 10
```

<Aside type="note">
  Passive mode requires Smart Home broadcasting to be enabled on the device.
</Aside>

## config

Manage the CLI configuration file.

```bash
aranet config <SUBCOMMAND>
```

| Subcommand | Description |
|------------|-------------|
| `show` | Print the config (`gui.service_api_key` hidden) |
| `get <KEY>` | Print a single config value |
| `set <KEY> <VALUE>` | Update a config value |
| `unset <KEY>` | Remove a config value |
| `path` | Print the config file path |
| `init` | Create a commented config file (an existing file is left alone) |

Supported keys: `device`, `format`, `timeout`, `no-color`, `fahrenheit`, `inhg`, `bq`.

```bash
aranet config init
aranet config set device living-room
aranet config set format json
aranet config show
```

`config.toml` lives in your platform's config directory: `aranet config path` prints where, and `ARANET_CONFIG_DIR` changes the directory. `config set`, `config unset`, `alias set`, `alias remove` and the alias prompt of `scan` change only the keys they touch: comments, key order and settings aranet doesn't know are kept. If the file doesn't parse, they fail with the parse error and leave it untouched. aranet writes the file atomically and owner-only (mode `0600`); a file that an earlier version created at `0644` becomes `0600` at its next change. `config init` writes a commented template and never replaces an existing file, and `config show` hides `gui.service_api_key`.

The GUI saves its own settings whenever you change one and when it quits: the `[gui]` table as a whole, and each `[behavior]` switch on its own. It keeps the rest of the file and its comments. It never changes `gui.service_url` or `gui.service_api_key`: it has no control for them, so set those two by hand. Other `[gui]` keys that you edit by hand while the GUI runs are overwritten by its next save, so quit it first (with Quit: while Close to Menu Bar is on, closing the window only hides it). If the file doesn't parse, the GUI leaves it untouched and shows `Settings not saved: could not update <file>. The log says why.`; the parse error is in its log.

The last device you connected to is kept in `cli-state.toml` in the data directory, not in `config.toml`, so connecting to a sensor doesn't rewrite your config:

| OS | Location |
|----|----------|
| Linux | `~/.local/share/aranet/cli-state.toml` |
| macOS | `~/Library/Application Support/aranet/cli-state.toml` |
| Windows | `%LOCALAPPDATA%\aranet\cli-state.toml` |

`ARANET_DATA_DIR` changes that directory. `config show` no longer lists `last_device`; a `last_device` that an earlier version wrote into `config.toml` is still used until your next connection.

<Aside type="note">
  On Windows, files inherit the permissions of their folder, and the default folders under your profile are private to your account. If you point `ARANET_CONFIG_DIR` or `ARANET_DATA_DIR` somewhere else, make that folder private in Command Prompt: `icacls <dir> /inheritance:r /grant:r "%USERNAME%:(OI)(CI)F" "SYSTEM:(OI)(CI)F" "Administrators:(OI)(CI)F"`
</Aside>

## sync

Sync device history into the local SQLite cache.

```bash
aranet sync [OPTIONS]
```

| Option | Description |
|--------|-------------|
| `-d, --device <ADDRESS>` | Device address or alias |
| `-T, --timeout <SECONDS>` | Connection timeout |
| `-f, --format <FORMAT>` | Output format: `text`, `json`, `csv` |
| `--full` | Re-download all history instead of syncing incrementally |
| `--all` | Sync all known devices from the database |

```bash
aranet sync --device living-room
aranet sync --device living-room --full
aranet sync --all --format json
```

## report

Generate summary reports from cached history.

```bash
aranet report [OPTIONS]
```

| Option | Description |
|--------|-------------|
| `-d, --device <ADDRESS>` | Device address or alias |
| `--all` | Report on every cached device |
| `-p, --period <PERIOD>` | `daily`, `weekly`, or `monthly` |
| `-f, --format <FORMAT>` | Output format: `text` or `json` |

```bash
aranet report --device living-room
aranet report --device living-room --period weekly --format json
aranet report --all --period monthly
```

<Aside>
  `report` works entirely from the local cache populated by `aranet sync`.
</Aside>

## cache

Query and maintain the local SQLite cache directly.

```bash
aranet cache <SUBCOMMAND>
```

| Subcommand | Description |
|------------|-------------|
| `devices` | List cached devices |
| `stats [--device <ADDRESS>]` | Show cache statistics |
| `history --device <ADDRESS>` | Query cached history records |
| `aggregate --device <ADDRESS>` | Show min/max/avg aggregates |
| `export --device <ADDRESS>` | Export cached history to CSV or JSON |
| `prune --older-than <DURATION>` | Delete older cache records |
| `info` | Show database path and size |
| `import` | Import history from CSV or JSON |

```bash
aranet cache devices
aranet cache stats --device living-room
aranet cache history --device living-room --count 50 --format json
aranet cache aggregate --device living-room --since 2026-03-01
aranet cache export --device living-room --format csv --output living-room.csv
aranet cache prune --older-than 90d --history-only --vacuum
aranet cache import --format json --input export.json
```

## server

Launch the bundled HTTP API server and dashboard from the CLI.

```bash
aranet server [OPTIONS]
```

| Option | Description |
|--------|-------------|
| `-c, --config <PATH>` | Path to the `aranet-service` configuration file |
| `-b, --bind <ADDR>` | Bind address override |
| `--database <PATH>` | Database path override |
| `--no-collector` | Start the API without background polling |
| `--daemon` | Detach and run in the background |

```bash
aranet server --bind 127.0.0.1:8080
aranet server --config ~/.config/aranet/server.toml --no-collector
```

`--bind` takes an IP address and port, such as `127.0.0.1:8080` (`localhost:8080` is rejected). A network address such as `0.0.0.0:8080` needs API-key authentication in the config file, or `security.allow_unauthenticated_network = true`; see [API Security](/aranet/docs/service/security/). `--bind` and `--database` apply to this run only and are never written into the config file. With `--daemon`, the configuration is checked before the server detaches: an invalid config or a refused bind address is printed and the command exits non-zero instead of reporting that the server started. A port that is already in use isn't detected before detaching: the detached server exits and its output is discarded, so run `aranet server` without `--daemon` to see the error. The same goes for `security.api_key_enabled = true` without an `api_key` when the config file can't be written: `--daemon` reports that the server started, and the detached server then exits because it can't save the key it generated. When the key is saved, the `Generated an API key` line isn't shown under `--daemon`, so read the key from the config file.

## completions

```bash
aranet completions <SHELL>
```

aranet completions zsh > ~/.zfunc/_aranet
